# Inurokkai -犬六回- (2026 AI 黑客松 Demo)

本项目为参加 2026 AI 黑客松的参赛作品（工程代号：`inurokkai_demo_v0.1_hackathon`）。
一款**伪3D横版动作 + 卡牌技能（半即时制）**游戏。玩家可以在移动、跳跃、冲刺中打出卡牌，卡牌与动作状态深度联动。

- **引擎版本**：Godot v4.7.2
- **编程语言**：GDScript
- **画面分辨率**：1152 × 648
- **单位换算**：1m = 60px

## 🚀 技术架构与项目亮点（降维打击）

作为一支独立团队，我们在短短的黑客松周期内，拒绝“屎山代码”，以极高的标准完成了工业级的底层架构。我们的核心亮点如下：

### 1. 极致的架构解耦：皮囊与大脑彻底分离
*   **Entity-Component 模式深度应用**：我们将角色视觉场景（`characters/`）与玩家通用逻辑（`player/`）进行了彻底剥离。角色实体只是一具“皮囊”（包含碰撞箱与动画），而“大脑”（移动、战斗、技能、生命四大组件）通过 `spawn_point.gd` 在运行时动态注入。
*   **降维优势**：未来新增任何体型/种族的新角色，**无需修改底层代码**，只需制作皮囊场景并配置数据蓝图，引擎自动组装，扩展性拉满。

### 2. 全面数据驱动 (Data-Driven)
*   **Single Source of Truth（单一数据源）**：角色的等级成长曲线、基础属性、初始装备、主题色等，全部被抽离至 `.tres` 资源文件。
*   **降维优势**：通过全局单例 `GameState` 统一进行所有数值计算（如暴击、装备加成），彻底杜绝了游戏内“血条显示与实际伤害不一致”的玄学Bug，数值策划和程序员工作完美解耦。

### 3. 自研 VN 引擎：从零手搓的 DSL 脚本
*   **纯文本解析与状态机驱动**：没有使用第三方插件，纯手搓了 `vn_parser`（DSL语法解析器）和 `vn_manager`（总指挥官）。支持基于状态机的立绘平滑平移、表情智能切换、打字机停顿演出。
*   **降维优势**：文案策划可直接使用类似 `bkxy 0 sad 「台词」` 的极简语法编写剧本，引擎自动处理坐标计算与高亮演出。配合自研的点击防丢帧机制与全屏输入拦截，体验极其丝滑。

### 4. UI 视觉工业化：原子组件与工厂模式
*   **纯代码绘制的 3D 楔形血条**：不依赖任何外部贴图，通过 `_draw()` 和向量数学实时渲染 3D 视角的血条，自带受击震荡、延迟黄条、低血闪烁等高级手感反馈。
*   **工厂模式统一全项目 UI**：拒绝重复造轮子，抽象出 `UITextFormat`（文字样式工厂）与 `UITextBox`（渐变黑框工厂）。所有菜单、对话框、提示条统一调用，全局样式一键修改，代码量锐减 40%。

### 5. 硬核动作手感打磨
*   实现了帧级判定的空刀惩罚（Miss 降低攻速）、抛物线物理击退、受击无敌帧闪烁、冲刺重击（霸体与拼刀）以及下坠 AOE 冲击波与屏幕震颤。

### 6. 完整的项目统筹与宣发落地
*   除硬核代码开发外，主导了整体玩法策划与全部剧本文案撰写、把控美术视觉方向。
*   规划了完整的线上宣发物料（徽章、挂件、假标题），并制定了极具吸引力的线下摆摊与互动策略。

## 🚀 如何运行与测试？

### ⚠️ 极其重要的测试纪律：
1. 如果你在开发 **UI 或 VN**：请在 Godot 中打开你自己做的场景（如 `ui_layer.tscn` 或 `vn.tscn`），点击右上角的 **“运行当前场景” (快捷键 F6)** 进行测试。
2. **绝对不要按 F5（运行整个项目）**！因为主程序（贺）的核心还在缝合中，按 F5 可能会因为缺少某些模块直接报错崩溃。

## 🛠️ Git 协作与提交规范 (GitHub Desktop)

**所有人绝对不要在 `main` 分支上直接开发！** 请使用 GitHub Desktop 图形界面，严格执行以下流程：

1. **切换分支**：在 GitHub Desktop 顶部 `Current Branch` 菜单，切换到你的专属分支（`feat/core`、`feat/ui`、`feat/vn`、`feat/art`）。
2. **拉取更新**：每天开工前，点击一下 `Fetch origin` 保持同步。
3. **日常开发**：写完代码或画完图后保存。
4. **提交代码**：回到 GitHub Desktop，左下角填写 Summary（如 `feat: 完成主菜单UI布局`），点击 **Commit to [你的分支名]**。
5. **推送到云端**：点击右上角的 **Push origin**。
6. **🚫 禁止合并**：**绝对不要点 Create Pull Request 或 Merge 到 main！** 你们提交完 Push 就可以了，由主程序统一进行代码合并和冲突解决。
